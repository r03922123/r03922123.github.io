LeetCode patterns

12 short posts, one per pattern: the idea in plain words, a reusable Python template, worked problems with their complexity, and problems to practice on. Every code block on these pages runs, and its asserts pass.

Two pointers, windows and prefix sums

  • Two pointers: move the side that limits youTwo indices walking toward each other over sorted or bounded data. Three sum, container with most water, and trapping rain water, each reduced to one rule about which pointer moves.
  • Sliding window: three templates and the exactly-k trickA window over a contiguous stretch that grows on the right and shrinks on the left. Templates for the shortest valid window, the longest valid window, and counting windows with exactly k of something.
  • Prefix state map: subarrays as differences of prefixesStore each prefix's state in a hash map, and a subarray becomes a pair of prefixes. Counting subarrays with sum k, nice subarrays, and the longest substring with even vowel counts using a bitmask.
  • Sweep line: turn intervals into eventsReplace each interval with a +change at its start and a −change at its end, then sweep in order. Difference arrays, sorted events, and answering point queries with binary search.
  • Majority vote and the sieve of EratosthenesTwo small classics. Boyer–Moore voting finds a majority element in one pass and O(1) space, and generalizes to elements above n/3. The sieve finds every prime below n in O(n log log n).

Sorting, searching and strings

  • Binary search on the answerWhat bisect_left and bisect_right count, and two loop templates — the first k where a predicate turns true, the last k where it is still true — applied to problems that never mention sorting.
  • Merge sort, quicksort and the Dutch flag partitionThe two comparison sorts worth writing from memory, what each guarantees, and the three-way partition that keeps quicksort fast when values repeat.
  • Quickselect: the kth element in linear expected timePartition like quicksort but recurse into one side only. Why that is O(n) on average, why repeated values break the naive version, and how it compares with a heap.
  • Bucket sort by frequencyWhen the sort key is a count bounded by n, index buckets by the key instead of comparing. Top k frequent elements and sorting characters by frequency in linear time.
  • Counting pairs with i < j: merge sort and sorted containersProblems that count pairs (i, j) with i < j and some inequality between values. Counting during merge sort, and the sorted-list alternative, applied to reverse pairs and a shifted-difference variant.
  • Rolling hash (Rabin–Karp)Hash every length-m window of a string in O(1) per step by sliding a polynomial hash. Substring search, then the real use, comparing many substrings at once, with binary search on length.
  • String matching with KMP and the Z-functionTwo linear-time tools that reuse what a failed comparison already revealed. The KMP failure table, the Z-array, and how each finds a pattern or scores a string against its own prefixes.
